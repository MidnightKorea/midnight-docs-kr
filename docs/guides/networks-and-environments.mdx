# Networks and environments

이 가이드로 Midnight이 운영하는 네트워크를 이해하고, 지금 하려는 작업에 맞는 네트워크를 고르고, DApp을 그 네트워크에 연결하고, 지갑에 자금을 넣고, 준비가 되면 mainnet으로 옮기세요. 네트워크 전반을 설명하고, 도구를 설정할 때 쓸 정확한 endpoint와 ID를 제공하며, 각 작업을 하나씩 짚은 뒤 마지막에 실제로 동작했는지 확인하는 테스트로 마무리합니다. 아무것도 없는 상태에서 시작한다면 먼저 [quickstart](../getting-started/quickstart)로 프로젝트를 스캐폴딩하고, 네트워크를 고르거나 전환해야 할 때 이 문서로 돌아오세요.

## Prerequisites

이 가이드의 모든 절차에 공통으로 적용됩니다:

- Node.js 22 버전 이상 설치.
- 로컬 네트워크와 [proof server](./run-proof-server)를 위한 Docker 설치 및 실행.
- 검증 테스트를 위한 [Vitest](https://vitest.dev/)와 `@midnight-ntwrk/midnight-js-network-id`를 테스트 워크스페이스에 설치.

## The Midnight networks

Midnight은 하나의 프로덕션 네트워크를 운영하고, 개발용으로 세 개의 환경을 유지합니다. 모든 환경이 동일한 스택을 실행하므로, DApp은 코드가 아니라 설정만 바꿔 환경 사이를 오갑니다.

전체 구성은 네 개의 네트워크로 이루어집니다:

- **`undeployed`**는 로컬 개발 네트워크입니다. Midnight node, indexer, proof server가 여러분의 머신에서 Docker로 실행됩니다. genesis 지갑에 미리 자금이 들어 있어, 시작한 지 몇 분 안에 배포할 수 있습니다. [Running a local network](#running-a-local-network)를 참고하세요.
- **`preview`**는 초기 개발과 실험을 위한 public 테스트 네트워크로, 코어 엔지니어링 팀이 운영합니다.
- **`preprod`**는 mainnet 배포 전 최종 검증을 위한 public 테스트 네트워크입니다. 테스트 네트워크 중 mainnet을 가장 가깝게 추종합니다.
- **`mainnet`**은 프로덕션 네트워크입니다. mainnet의 토큰은 실제 가치를 지니며 faucet이 없습니다.

각 public 네트워크는 RPC로 자신을 식별합니다. `system_chain` 메서드는 `Midnight Preview`, `Midnight Preprod`, `Midnight Mainnet` 중 하나를 반환합니다. 모든 네트워크는 DApp이 통신하는 동일한 세 가지 서비스를 노출합니다. node(HTTPS·WebSocket 상의 JSON-RPC), indexer(HTTP·WebSocket 상의 GraphQL), 그리고 proof server입니다. node와 indexer는 네트워크마다 다르지만, proof server는 여러분의 private 데이터를 다루기 때문에 어떤 네트워크를 대상으로 하든 로컬 6300 포트에서 실행됩니다. 모든 endpoint는 [Environment reference](#environment-reference)에 정리되어 있습니다.

:::note The testnet-02 name is retired

예전 문서나 도구는 `testnet-02`라는 네트워크를 참조하기도 합니다. Midnight은 이 네트워크를 폐기했고, `rpc.testnet-02.midnight.network`와 `indexer.testnet-02.midnight.network` 같은 endpoint는 더 이상 연결되지 않습니다. 대신 [Environment reference](#environment-reference)에 정리된 endpoint로 `preview`나 `preprod`를 사용하세요.

:::

## Network selection at a glance

주어진 작업에 어떤 네트워크를 대상으로 할지 정리한 표입니다. 무언가를 설정하기 전에 먼저 참고하세요. 각 선택에 따른 설정과 자금 조달의 결과를 함께 표시했습니다.

| 작업 | 네트워크 | 자금 조달 | 위험에 노출되는 가치 |
|---|---|---|---|
| 컨트랙트 반복 개발, 테스트 실행, CI | `undeployed` | genesis 지갑에 미리 자금이 있어 faucet 불필요 | 없음 |
| 개발 초기에 공유 public 인프라를 대상으로 테스트 | `preview` | [Preview faucet](https://midnight-tmnight-preview.nethermind.dev/)에서 무료 tNIGHT, 요청량 제한 | 없음 |
| 프로덕션 출시 전 최종 검증 | `preprod` | [Preprod faucet](https://midnight-tmnight-preprod.nethermind.dev/)에서 무료 tNIGHT, 요청량 제한 | 없음 |
| 프로덕션 운영 | `mainnet` | 실제 NIGHT, 등록 후 DUST 생성 | 실제 |

속도를 위해 `undeployed`에서 시작하고, 공유 인프라나 지속되는 체인이 필요하면 `preview`나 `preprod`로 옮기고, 출시 전에 `preprod`에서 검증하고, `mainnet`은 신중한 최종 단계로 다루세요. 각 선택의 비용은 [Funding and transaction cost](#funding-and-transaction-cost)에서 설명합니다.

## Environment reference

각 환경의 endpoint, network ID, 자금 조달 출처입니다. 지갑, indexer, 도구를 이 값에 맞춰 설정하세요. 다른 페이지들은 이 값을 다시 적지 않고 이곳으로 링크합니다.

Blockfrost가 `preprod`와 `mainnet`의 public indexer와 node RPC를 제공하며, 모든 요청에는 해당 네트워크의 [Blockfrost project token](#getting-a-blockfrost-project-token)이 필요합니다. Midnight은 자체 mainnet endpoint인 `indexer.mainnet.midnight.network`와 `rpc.mainnet.midnight.network`를 2026년 9월 30일에, Preprod endpoint인 `indexer.preprod.midnight.network`와 `rpc.preprod.midnight.network`를 2026년 10월 9일에 폐기했습니다. `preview` endpoint만 Midnight이 호스팅하며 토큰이 필요 없습니다.

## Blockfrost: the Preprod and Mainnet indexer and RPC provider {#blockfrost-the-mainnet-indexer-and-rpc-provider}

[Blockfrost](https://blockfrost.io)는 public Midnight Preprod·Mainnet indexer(HTTP·WebSocket 상의 GraphQL)와 node RPC(HTTPS·WebSocket 상의 JSON-RPC)를 운영합니다. Midnight이 호스팅하던 endpoint가 제공하던 것과 동일한 indexer API를 실행하므로, DApp은 코드를 바꾸지 않고 endpoint URL을 바꾸고 토큰을 추가하는 것만으로 옮겨 갑니다. 자신의 Blockfrost 계정과 프로젝트로 Blockfrost에 직접 연결합니다.

Midnight이 호스팅하던 endpoint와 다른 점은 세 가지입니다:

- **모든 요청에는 project token이 필요합니다.** Blockfrost는 유효한 토큰이 없는 요청에 HTTP `403`을 반환합니다. 정확한 오류 메시지는 [Migrating from the Midnight-hosted endpoints](#migrating-from-the-midnight-hosted-mainnet-endpoints)에 정리되어 있습니다. Blockfrost는 네트워크별로 토큰을 발급합니다. Mainnet에서는 Preprod 토큰을, Preprod에서는 Mainnet 토큰을 거부합니다.
- **사용량 한도는 Blockfrost 플랜에 따릅니다.** 요청은 공유 public endpoint가 아니라 여러분의 계정에 집계됩니다. 출시 전에 [blockfrost.io](https://blockfrost.io)에서 플랜의 한도를 확인하고, DApp에 더 필요하면 유료 플랜으로 옮기거나 자체 indexer를 운영하세요.
- **proof server는 Blockfrost 서비스가 아닙니다.** 여러분의 private 데이터를 다루므로 로컬 6300 포트에서 계속 실행됩니다.

자체 node와 indexer 운영은 여전히 지원됩니다. [Nodes](../nodes)를 참고하세요.

### Getting a Blockfrost project token

1. [blockfrost.io](https://blockfrost.io)에서 가입하거나 로그인합니다.

2. 프로젝트를 만들고 **Midnight Preprod** 또는 **Midnight Mainnet** 네트워크를 선택합니다. 사용하는 네트워크마다 별도의 프로젝트를 만드세요.

3. 프로젝트 대시보드에서 project ID를 복사합니다. 이것이 토큰입니다. Midnight Preprod project ID는 `nightpreprod`로, Midnight Mainnet project ID는 `nightmainnet`로 시작합니다.

4. 소스 코드 밖에, 예를 들어 gitignore된 `.env` 파일에 저장합니다:

   ```bash title=".env"
   BLOCKFROST_PROJECT_ID=<your Midnight Preprod or Midnight Mainnet project ID>
   ```

5. 토큰이 동작하는지 확인합니다. indexer는 블록 높이를, node는 네트워크 이름을 반환합니다.

   <Tabs groupId="network">
   <TabItem value="preprod" label="Preprod">

   ```bash
   curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"query":"{ block { height } }"}' \
     "https://midnight-preprod.blockfrost.io/api/v0?project_id=$BLOCKFROST_PROJECT_ID"

   curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"system_chain","params":[]}' \
     "https://rpc.midnight-preprod.blockfrost.io?project_id=$BLOCKFROST_PROJECT_ID"
   ```

   node는 `"Midnight Preprod"`를 반환합니다.

   </TabItem>
   <TabItem value="mainnet" label="Mainnet">

   ```bash
   curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"query":"{ block { height } }"}' \
     "https://midnight-mainnet.blockfrost.io/api/v0?project_id=$BLOCKFROST_PROJECT_ID"

   curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"system_chain","params":[]}' \
     "https://rpc.midnight-mainnet.blockfrost.io?project_id=$BLOCKFROST_PROJECT_ID"
   ```

   node는 `"Midnight Mainnet"`을 반환합니다.

   </TabItem>
   </Tabs>

### Passing the token

Blockfrost는 토큰을 `project_id` 요청 헤더로도, `?project_id=<token>` 쿼리 파라미터로도 받습니다. Midnight SDK에서는 쿼리 파라미터를 사용하세요. `indexerPublicDataProvider`, wallet SDK indexer 클라이언트, Polkadot.js `WsProvider`는 평범한 URL을 받으며, 브라우저 WebSocket은 커스텀 헤더를 설정할 수 없습니다.

작은 헬퍼를 두면 직접 작성하는 URL에서 토큰을 빼 둘 수 있습니다:

```typescript title="config.ts"
function withBlockfrostKey(url: string, projectId: string): string {
  return `${url}${url.includes('?') ? '&' : '?'}project_id=${encodeURIComponent(projectId)}`;
}

function blockfrostProjectId(): string {
  const projectId = process.env.BLOCKFROST_PROJECT_ID?.trim();
  if (!projectId) throw new Error('BLOCKFROST_PROJECT_ID is not set.');
  return projectId;
}

export function preprodConfig() {
  const projectId = blockfrostProjectId();
  return {
    networkId: 'preprod',
    node: withBlockfrostKey('https://rpc.midnight-preprod.blockfrost.io', projectId),
    nodeWS: withBlockfrostKey('wss://rpc.midnight-preprod.blockfrost.io', projectId),
    indexer: withBlockfrostKey('https://midnight-preprod.blockfrost.io/api/v0', projectId),
    indexerWS: withBlockfrostKey('wss://midnight-preprod.blockfrost.io/api/v0/ws', projectId),
    proofServer: 'http://localhost:6300',
  } as const;
}

export function mainnetConfig() {
  const projectId = blockfrostProjectId();
  return {
    networkId: 'mainnet',
    node: withBlockfrostKey('https://rpc.midnight-mainnet.blockfrost.io', projectId),
    nodeWS: withBlockfrostKey('wss://rpc.midnight-mainnet.blockfrost.io', projectId),
    indexer: withBlockfrostKey('https://midnight-mainnet.blockfrost.io/api/v0', projectId),
    indexerWS: withBlockfrostKey('wss://midnight-mainnet.blockfrost.io/api/v0/ws', projectId),
    proofServer: 'http://localhost:6300',
  } as const;
}
```

설정은 import 시점이 아니라 사용할 때 빌드하세요. 그래야 토큰이 없을 때 sync 깊은 곳에서 `403`이 나는 대신 명확한 메시지로 실패합니다. 각 함수는 자기 네트워크의 토큰이 필요하므로, `preprodConfig()`에는 Midnight Preprod project ID를, `mainnetConfig()`에는 Midnight Mainnet project ID를 `BLOCKFROST_PROJECT_ID`에 설정하세요.

:::warning Keep the token out of browser code and logs

브라우저 쪽 URL에 담긴 토큰은 페이지를 여는 누구에게나 보이며, 이를 복사한 사람은 누구든 여러분의 할당량을 소비합니다. 브라우저 DApp이라면 indexer와 RPC 호출을 서버에서 토큰을 붙이는, 여러분이 통제하는 백엔드를 통해 보내거나, public으로 취급할 각오가 된 토큰을 사용하세요. DApp이 [DApp Connector API](/api-reference/dapp-connector)(`getConfiguration()`)를 통해 사용자 지갑에서 endpoint를 받는다면, 어느 indexer와 node를 쓸지는 지갑이 결정합니다.

오류 메시지와 로그에는 토큰이 포함된 전체 URL이 담길 수 있습니다. 예를 들어 Midnight.js의 실패한 indexer 요청은 `request to <url> failed, reason: <reason>`을 보고하고, testkit-js는 원격 테스트 환경이 시작될 때 전체 환경 설정을 로그로 남깁니다. 로그로 남기기 전에 URL과 오류에서 `project_id` 값을 제거하세요.

:::

모든 소비자를 한꺼번에 옮기세요. 애플리케이션 설정, 테스트 하네스, 스크립트 전부입니다. 그런 다음 아래 문제들을 점검하세요.

| 증상 | 원인과 해결 |
|---|---|
| HTTP `410`과 `ENDPOINT_DECOMMISSIONED` 오류, 또는 Midnight.js의 `Response not successful: Received status code 410` | 설정이 아직 `indexer.mainnet.midnight.network` 또는 `indexer.preprod.midnight.network`를 가리킵니다. 두 호스트명 모두 아직 연결되지만, WebSocket 연결을 포함해 모든 요청에 `410`으로 응답합니다. 위 표의 Blockfrost 대응 URL로 바꾸세요. |
| `rpc.mainnet.midnight.network` 또는 `rpc.preprod.midnight.network`로 보낸 요청이 아직 성공함 | Midnight이 호스팅하던 RPC endpoint는 폐기되었으며 언제든 응답을 멈출 수 있습니다. 각 URL을 위 표의 Blockfrost 대응 URL로 바꾸세요. |
| HTTP `403`과 `Missing project token. Please include project_id in your request.` | URL에 토큰이 없습니다. WebSocket URL을 포함해 모든 indexer·RPC URL에, 대상 네트워크의 프로젝트에서 받은 `?project_id=<token>`을 덧붙이세요. |
| HTTP `403`과 `Invalid project token.` | Blockfrost가 토큰을 인식하지 못합니다. project ID 전체를 복사했는지 확인하세요. |
| HTTP `403`과 `Network token mismatch. Are you using token for the correct network?` | 토큰이 다른 네트워크의 프로젝트에 속합니다. 예컨대 Mainnet URL에 `nightpreprod`로 시작하는 project ID를, 또는 Preprod URL에 `nightmainnet`을 쓴 경우입니다. Preprod에는 **Midnight Preprod** 프로젝트의 project ID(`nightpreprod`로 시작)를, Mainnet에는 **Midnight Mainnet** 프로젝트의 project ID(`nightmainnet`으로 시작)를 사용하세요. |
| Midnight.js의 `Response not successful: Received status code 403` | 위 두 `403` 오류 중 하나입니다. Midnight.js는 몇 초 동안 재시도하며 오류 메시지를 보여주지 않으므로, 어느 쪽인지 확인하려면 [Getting a Blockfrost project token](#getting-a-blockfrost-project-token)의 `curl` 점검을 실행하세요. |
| 지갑 sync가 끝나지 않고, 로그에 `values inserted non-linearly into dust generation tree`(또는 `zswap commitment tree`, `dust commitment tree`)가 나타남 | 옛 indexer에서 저장한 sync 상태는 이식할 수 없습니다. 이벤트·트랜잭션 id가 indexer마다 다르기 때문입니다. 이는 Midnight이 호스팅하던 indexer에 대해 sync 상태를 저장했다가 Blockfrost에서 재개하는 지갑에만 영향을 줍니다. `serializeState()` 출력, fast-sync 또는 preseed 번들, 저장된 이벤트·트랜잭션 id 등입니다. 그 상태를 버리고 genesis부터 sync하세요. 커서를 손으로 옮기지 마세요. 첫 sync는 오래 걸릴 수 있습니다. preprod 전체 sync는 한 시간이 넘습니다. 시작할 때마다 genesis부터 sync하는 지갑, 그리고 컨트랙트 상태만 읽거나 트랜잭션만 제출하는 DApp은 영향을 받지 않습니다. |
| 자금은 도착했는데 트랜잭션 직후 `Wallet sync timeout`이 발생함 | 유휴 구독에서는 indexer가 unshielded sync 진행 상황을 덜 자주 보내며, 업데이트 간격이 약 4분까지(무작위 jitter로 최대 약 5분) 늘어납니다. 트랜잭션 직후에는 지갑의 "완전 동기화" 신호가 그만큼 지연될 수 있습니다. 이는 Blockfrost에서 발생하며, 직접 운영하는 일부 indexer 릴리스도 같은 동작을 보입니다. 짧은 synced-state 타임아웃 대신, 예상 잔액이나 지출 가능한 DUST를 기다리거나 5분 넘게 여유를 두세요. |
| 지갑을 빌드할 때 `TypeError: Invalid URL` | 지갑의 relay URL로 전달한 URL이 비어 있거나 placeholder여서 `new URL()`이 예외를 던집니다. testkit-js는 relay URL을 `nodeWS`에서 만들고, 일부 가이드는 node URL에서 만듭니다. [Passing the token](#passing-the-token)에서처럼 그 URL을 토큰이 포함된 완전한 `wss://` Blockfrost RPC URL로 설정하세요. |
| 커스텀 GraphQL 클라이언트가 `dustGenerations`에서 실패함 | Blockfrost에서는 `Subscription.dustGenerations`가 `(dustAddress, startIndex, endIndex)` 대신 `(dustAddress, blockHash, dtimeCutoffHeight)`를 받습니다. 이 구독을 쓰는 `@midnight-ntwrk` 패키지는 없으므로, 여러분 자신의 쿼리만 업데이트하세요. 스키마의 나머지는 그대로이며, Blockfrost는 추가 필드를 더합니다. |

Midnight Service Desk의 [Blockfrost migration runbook](https://github.com/midnightntwrk/servicedesk/blob/main/runbooks/indexer-blockfrost-migration-runbook/indexer-blockfrost-migration-runbook.md)은 저장된 커서가 이식 가능한지 확인하는 스크립트를 포함해 이 오류들을 더 깊이 다룹니다. 이 스크립트는 옛 indexer와 새 indexer를 비교하므로, Mainnet이나 Preprod에서는 더 이상 동작하지 않습니다.

## Running a local network

[midnight-local-dev](https://github.com/midnightntwrk/midnight-local-dev)로 Midnight 스택 전체, 즉 node, indexer, proof server를 여러분의 머신에서 Docker로 실행하세요. 이 도구는 미리 자금이 들어간 genesis 지갑을 초기화하고 자금 조달 메뉴를 제공하므로, faucet 없이 위험 부담 없이 몇 분 안에 배포하고 트랜잭션을 보낼 수 있습니다.

### Procedure

1. 저장소를 클론하고 의존성을 설치합니다:

   ```bash
   git clone https://github.com/midnightntwrk/midnight-local-dev.git
   cd midnight-local-dev
   npm install
   ```

2. 네트워크를 시작합니다:

   ```bash
   npm start
   ```

   이 명령은 Docker 이미지를 받아오고(버전은 `standalone.yml`에 고정되어 있음), health check와 함께 node, indexer, proof server를 시작하고, 미리 채굴된 NIGHT을 보유한 genesis master 지갑을 초기화하고, 수수료를 낼 수 있도록 그 지갑을 DUST용으로 등록한 뒤, 자금 조달 메뉴를 제공합니다:

   ```text
   Choose an option:
     [1] Fund accounts from config file (NIGHT + DUST registration)
     [2] Fund accounts by public key (NIGHT transfer only)
     [3] Display wallets
     [4] Exit
   ```

3. 개발에 사용할 지갑에 자금을 넣습니다. `1`번은 계정이 담긴 JSON 파일을 읽어(`accounts.example.json`을 `accounts.json`으로 복사하고 24단어 니모닉을 추가) 각 계정에 tNIGHT을 전송하고 DUST 생성을 위해 등록합니다. `2`번은 붙여넣은 Bech32m 주소로 tNIGHT을 전송하며, 수신자가 직접 DUST용으로 등록합니다. 어느 쪽이든 각 계정은 50,000 tNIGHT을 받고, 작업당 최대 10개 계정까지 처리합니다.

4. 컨테이너만 필요하다면 지갑 도구를 건너뛰고 Docker Compose를 직접 사용하세요. 이 방식에서는 genesis 자금 조달과 DUST 등록을 직접 처리합니다:

   ```bash
   docker compose -f standalone.yml up -d    # start
   docker compose -f standalone.yml ps       # status
   docker compose -f standalone.yml logs -f  # logs
   docker compose -f standalone.yml down     # stop
   ```

### Verification

로컬 endpoint가 응답합니다. node는 dev 체인을 보고하며 health check를 제공하고, indexer는 블록을 제공하고, proof server는 연결을 받아들입니다.

```typescript title="local-network.test.ts"
import { describe, it, expect } from 'vitest';

describe('local network', () => {
  it('node is healthy', async () => {
    const res = await fetch('http://localhost:9944/health').then((r) => r.json());
    expect(res.isSyncing).toBe(false);
  });

  it('indexer serves blocks', async () => {
    const res = await fetch('http://localhost:8088/api/v4/graphql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ query: '{ block { height } }' }),
    }).then((r) => r.json());
    expect(res.data.block.height).toBeGreaterThan(0);
  });

  it('proof server reports ok', async () => {
    const res = await fetch('http://localhost:6300/health').then((r) => r.json());
    expect(res.status).toBe('ok');
  });
});
```

```text
 ✓ local-network.test.ts > local network > node is healthy
 ✓ local-network.test.ts > local network > indexer serves blocks
 ✓ local-network.test.ts > local network > proof server reports ok

 Test Files  1 passed (1)
      Tests  3 passed (3)
```

## Local network troubleshooting

로컬 스택에서 마주치기 쉬운 실패 유형과 그 해결책입니다.

| 증상 | 해결 |
|---|---|
| `Bind for 0.0.0.0:9944 failed: port is already allocated` | 이전 실행이 아직 포트를 점유하고 있습니다. `docker compose -f standalone.yml down`을 실행하거나, `lsof -i :9944`로 점유 중인 프로세스를 찾으세요. |
| indexer가 첫 시작에서 `block number 1 not found`로 종료됨 | 새 체인에서 발생하는 시작 시점 경합입니다. indexer가 node가 아직 생성하지 않은 블록을 요청한 것입니다. `docker start midnight-indexer`로 다시 시작하면 블록이 생긴 뒤 정상적으로 물립니다. |
| `Operation failed: Expected undeployed address, got Preprod address` | 지갑이 잘못된 네트워크에 있습니다. Lace의 **Settings**에서 Undeployed 네트워크로 전환한 뒤 그 unshielded 주소를 사용하세요. |
| 컨테이너가 시작되지 않음 | Docker가 실행 중인지 확인한 뒤 `docker compose -f standalone.yml pull`과 `up`을 실행하고, 실패한 서비스의 로그를 `docker compose -f standalone.yml logs -f`로 확인하세요. |
| 시작 후 지갑 sync가 느림 | indexer가 node를 따라잡는 중입니다. `curl http://localhost:9944/health`로 node가 블록을 생성하는지 확인하고 indexer 로그를 지켜보세요. |

## Connecting a DApp to a network

network ID를 설정하고 그에 맞는 endpoint를 연결해 DApp을 원하는 네트워크로 향하게 하세요. 흔한 함정은 서로 다른 네트워크의 값을 섞는 것입니다. 예를 들어 `preprod` network ID에 `preview` indexer URL을 쓰는 경우입니다. ID와 endpoint를 한곳에 함께 두어 서로 어긋나지 않게 하세요.

### Procedure

1. [Network selection at a glance](#network-selection-at-a-glance)를 참고해 대상 네트워크를 고릅니다.

2. provider를 초기화하기 전에 network ID를 설정합니다. Midnight.js는 주소를 정규화하고 트랜잭션을 구성할 때(즉 `deployContract`와 `callTx` 경로) 이 값을 읽으므로, 어떤 컨트랙트 작업보다 먼저 설정해야 합니다:

   ```typescript
   import { setNetworkId } from '@midnight-ntwrk/midnight-js-network-id';

   setNetworkId('preprod');

   /** Supported network IDs: 'mainnet', 'preview', 'preprod', 'undeployed' */
   ```

   기본값은 없습니다. `setNetworkId`를 호출하기 전까지 `getNetworkId()`는 `Network ID has not been configured`를 던집니다. 이 호출은 문자열을 있는 그대로 저장하므로, 네트워크 이름을 잘못 쓰더라도 여기서 실패하지 않고 나중에 그 ID를 소비하는 컴포넌트에서 드러납니다.

3. [Environment reference](#environment-reference)의 값을 사용해 network ID와 그 endpoint를 하나의 설정 객체에 함께 두세요. proof server URL은 모든 네트워크에서 로컬로 유지된다는 점에 유의하세요. `preprod` endpoint는 Blockfrost 토큰이 필요하므로, 이 예제는 [Passing the token](#passing-the-token)의 `preprodConfig()` 헬퍼로 이를 빌드합니다:

   ```typescript
   import { preprodConfig } from './config.js';

   const NETWORKS = {
     undeployed: () => ({
       node: 'http://localhost:9944',
       indexer: 'http://localhost:8088/api/v4/graphql',
       indexerWS: 'ws://localhost:8088/api/v4/graphql/ws',
       proofServer: 'http://localhost:6300',
     }),
     preview: () => ({
       node: 'https://rpc.preview.midnight.network',
       indexer: 'https://indexer.preview.midnight.network/api/v4/graphql',
       indexerWS: 'wss://indexer.preview.midnight.network/api/v4/graphql/ws',
       proofServer: 'http://localhost:6300',
     }),
     preprod: preprodConfig,
   } as const;

   const network = NETWORKS['preprod']();
   ```

4. endpoint를 provider에 전달합니다. private state, ZK 설정, 지갑 provider를 포함한 전체 provider 객체는 [Configuring providers for a contract](./deploy-and-operate#configuring-providers-for-a-contract)에서 다룹니다:

   ```typescript
   import { indexerPublicDataProvider } from '@midnight-ntwrk/midnight-js-indexer-public-data-provider';

   const publicDataProvider = indexerPublicDataProvider(network.indexer, network.indexerWS);
   ```

5. `create-mn-app`으로 스캐폴딩한 프로젝트(`hello-world` 템플릿)에서는 대신 setup 스크립트로 네트워크를 선택합니다. 이 선택은 전환하기 전까지 유지됩니다:

   ```bash
   npm run setup -- --network preview   # runs on preview and makes it active
   npm run network preprod              # switch the active network later
   ```

   스캐폴드의 네트워크 스크립트는 `undeployed`, `preview`, `preprod`를 받습니다. mainnet은 스캐폴드 대상이 아닙니다. 위에서 보인 대로 provider로 직접 연결하세요.

### Verification

각 network ID가 SDK를 통해 왕복하고, 설정한 endpoint가 예상한 체인 정체성과 현재 블록 높이로 응답합니다. Blockfrost가 `preprod`와 `mainnet` endpoint를 제공하며 각각 자기 네트워크의 토큰이 필요하므로, 이 테스트는 두 변수를 읽습니다. `BLOCKFROST_PREPROD_PROJECT_ID`에 Midnight Preprod project token을, `BLOCKFROST_MAINNET_PROJECT_ID`에 Midnight Mainnet project token을 설정하세요. [Getting a Blockfrost project token](#getting-a-blockfrost-project-token)을 참고하세요. 토큰이 없는 네트워크의 node·indexer 검사는 건너뜁니다. 두 토큰이 모두 없으면 `5 passed | 4 skipped`를 보고하므로, Blockfrost 계정 없이도 `preview`를 테스트할 수 있습니다.

```typescript title="networks.test.ts"
import { describe, it, expect } from 'vitest';
import { setNetworkId, getNetworkId } from '@midnight-ntwrk/midnight-js-network-id';

const token = (name: string) => encodeURIComponent(process.env[name]?.trim() ?? '');
const preprodToken = token('BLOCKFROST_PREPROD_PROJECT_ID');
const mainnetToken = token('BLOCKFROST_MAINNET_PROJECT_ID');

const rpc = (url: string, method: string) =>
  fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ jsonrpc: '2.0', method, params: [], id: 1 }),
  }).then((r) => r.json());

const indexerBlock = (url: string) =>
  fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ query: '{ block { height } }' }),
  }).then((r) => r.json());

const networks = [
  {
    id: 'preview',
    chain: 'Midnight Preview',
    node: 'https://rpc.preview.midnight.network',
    indexer: 'https://indexer.preview.midnight.network/api/v4/graphql',
  },
  {
    id: 'preprod',
    chain: 'Midnight Preprod',
    node: `https://rpc.midnight-preprod.blockfrost.io?project_id=${preprodToken}`,
    indexer: `https://midnight-preprod.blockfrost.io/api/v0?project_id=${preprodToken}`,
    projectId: preprodToken,
  },
  {
    id: 'mainnet',
    chain: 'Midnight Mainnet',
    node: `https://rpc.midnight-mainnet.blockfrost.io?project_id=${mainnetToken}`,
    indexer: `https://midnight-mainnet.blockfrost.io/api/v0?project_id=${mainnetToken}`,
    projectId: mainnetToken,
  },
];

describe.each(networks)('$id', ({ id, chain, node, indexer, projectId }) => {
  // The Blockfrost endpoints need a token; skip them when none is set.
  const noToken = projectId === '';

  it('sets the network ID', () => {
    setNetworkId(id);
    expect(getNetworkId()).toBe(id);
  });

  it.skipIf(noToken)('reaches the node RPC', async () => {
    const res = await rpc(node, 'system_chain');
    expect(res.result).toBe(chain);
  });

  it.skipIf(noToken)('reaches the indexer', async () => {
    const res = await indexerBlock(indexer);
    expect(res.data.block.height).toBeGreaterThan(0);
  });
});
```

## Funding and transaction cost

Midnight의 모든 트랜잭션은 DUST를 소비하며, DUST가 어디서 오느냐가 네트워크 사이의 가장 실질적인 차이입니다. 이 두 토큰 모델을 한 번 이해해 두면 이후 각 네트워크에서 혼란에 빠지는 시간을 아낄 수 있습니다.

NIGHT은 네이티브 유틸리티 토큰이며, 이를 보유하는 것이 DUST에 대한 자격이 됩니다. DUST는 shielded, 전송 불가 리소스로, 수수료가 이것으로 지불됩니다. 등록된 NIGHT은 시간이 지나면서 NIGHT당 약 5 DUST의 캡까지 DUST를 생성하고 약 일주일에 걸쳐 다시 채워지므로, 자금이 든 지갑은 트랜잭션 처리 능력을 영구히 소진하는 것이 아니라 다시 회복합니다. [Tokens on Midnight](../tokens/overview)이 이 모델을 소개하고, [DUST architecture](../concepts/dust-architecture)가 생성·감쇠와 프로토콜 파라미터를 다룹니다.

**로컬 네트워크**에서는 genesis 지갑에 미리 자금이 있고 이미 DUST용으로 등록되어 있으며, 자금 조달 메뉴가 여러분의 테스트 지갑으로 tNIGHT을 전송합니다. DUST는 약 5분이면 생성됩니다. 필요가 없으므로 faucet도 없습니다. [Running a local network](#running-a-local-network)를 참고하세요.

**`preview`와 `preprod`**에서는 네트워크의 faucet에서 무료 tNIGHT을 요청하고(요청당 5,000 tNIGHT을 보내며, 두 faucet 모두 요청량이 제한됨) 지갑에서 tDUST 생성을 위해 등록하세요. [Funding a wallet](./acquire-tokens) 가이드가 faucet, Lace의 **Generate tDUST** 흐름, 그리고 스크립트로 처리하는 wallet SDK 경로를 안내합니다. 테스트 토큰은 실제 가치가 없습니다.

**`mainnet`**에는 faucet이 없습니다. 현재 대부분의 NIGHT은 Cardano에 cNIGHT으로 보유되며, DUST 생성은 cross-chain으로 이루어집니다. Cardano reward 주소를 Midnight DUST public key와 함께 등록하면([cNgD DApp](https://midnight-dust-mainnet.nethermind.io/)이 이를 처리) 보유한 cNIGHT이 Midnight에서 DUST를 생성합니다. 이 등록은 Cardano에서 확정된 뒤 Midnight node에 도달해야 하며 약 12시간이 걸리므로, 프로덕션 지갑은 출시일보다 훨씬 앞서 자금을 넣어 두세요.

## Preparing a DApp for mainnet

`preprod`에서 동작하는 DApp을 프로덕션 네트워크로 옮깁니다. 방식 자체는 다른 네트워크 전환과 똑같은 설정 변경입니다. mainnet이 다른 점은 자금 조달이 cross-chain이라 느리고, 실수가 실제 가치를 대가로 치르며, public 테스트 인프라의 보장이 적용되지 않는다는 것입니다.

### Prerequisites

- `preprod`에 배포·검증된 DApp이 [Connecting a DApp to a network](#connecting-a-dapp-to-a-network)에서처럼 연결되어 있어야 합니다.

### Procedure

1. 먼저 `preprod`에서 전체 배포·상호작용 흐름을 검증합니다. mainnet에 가장 가까운 네트워크이므로, 여기서 실패하는 것은 프로덕션에서도 실패합니다.

2. 프로덕션 지갑에 자금을 넣습니다. [cNgD DApp](https://midnight-dust-mainnet.nethermind.io/)을 통해 cNIGHT을 DUST 생성용으로 등록하고, [Funding and transaction cost](#funding-and-transaction-cost)에서 설명한 대로 등록이 반영되기까지 약 12시간을 기다리세요. 트랜잭션을 시도하기 전에 지갑에 DUST 잔액이 표시되는지 확인하세요.

3. **Midnight Mainnet** Blockfrost 프로젝트를 만들고, [Getting a Blockfrost project token](#getting-a-blockfrost-project-token)에서처럼 그 토큰을 서버 쪽에 저장합니다. public mainnet indexer와 RPC는 토큰이 없는 요청을 거부하며, `preprod`에서 쓰던 Midnight Preprod 토큰도 거부합니다.

4. 설정을 mainnet으로 향하게 합니다. network ID를 설정하고 [Passing the token](#passing-the-token)의 `mainnetConfig()` 헬퍼로 endpoint를 빌드하세요. 이 헬퍼는 node, node WebSocket, indexer, indexer WebSocket URL에 토큰을 덧붙입니다. DApp의 다른 부분은 바뀌지 않습니다:

   ```typescript
   import { setNetworkId } from '@midnight-ntwrk/midnight-js-network-id';
   import { mainnetConfig } from './config.js';

   setNetworkId('mainnet');

   const network = mainnetConfig();
   ```

   `create-mn-app` 스캐폴드는 mainnet 대상을 제공하지 않으므로, [Configuring providers for a contract](./deploy-and-operate#configuring-providers-for-a-contract)에서처럼 provider를 직접 연결하세요. 기존 mainnet DApp을 옛 Midnight 호스팅 endpoint에서 옮기는 경우라면 [Migrating from the Midnight-hosted endpoints](#migrating-from-the-midnight-hosted-mainnet-endpoints)도 함께 진행하세요.

5. 인프라를 결정합니다. Blockfrost 사용량 한도는 플랜에 따르므로, 예상 트래픽에 맞게 플랜 크기를 정하거나 자체 [node](../nodes)와 indexer를 운영하세요.

6. 무언가를 공지하기 전에 [Mainnet readiness checklist](#mainnet-readiness-checklist)를 처리하세요.

### Verification

mainnet endpoint가 프로덕션 체인 정체성과 현재 블록 높이로 응답합니다. 이 가이드의 연결 테스트를 mainnet으로 필터링해, Blockfrost 토큰을 설정한 채로 실행하세요:

```bash
BLOCKFROST_MAINNET_PROJECT_ID=<your Midnight Mainnet project ID> npx vitest run networks.test.ts -t mainnet
```

## Mainnet readiness checklist

프로덕션 출시 전에 이 목록을 처리하세요. 각 항목은 그것을 설명하는 페이지로 링크됩니다.

- [ ] **전체 흐름이 `preprod`에서 검증되었다.** mainnet에 가장 가까운 네트워크에서 배포·상호작용·상태 관찰을 처음부터 끝까지 수행합니다.
- [ ] **보안 체크리스트가 완료되었다.** 컨트랙트와 그 주위 DApp에 대해 [pre-deployment security checklist](./security-best-practices#pre-deployment-security-checklist)를 처리합니다.
- [ ] **업데이트 가능성 결정이 내려졌다.** 컨트랙트가 실제 가치를 보유하기 전에 업그레이드 가능 여부와 방식을 결정합니다. [Contract updatability and the maintenance authority](./deploy-and-operate#contract-updatability-and-the-maintenance-authority)를 참고하세요.
- [ ] **프로덕션 지갑이 DUST를 생성한다.** cNIGHT이 등록되었고, 약 12시간의 등록 지연이 지났으며, 지갑에 DUST 잔액이 표시됩니다. [Funding and transaction cost](#funding-and-transaction-cost)를 참고하세요.
- [ ] **설정의 모든 endpoint가 mainnet endpoint다.** `midnight-preprod.blockfrost.io` URL이나 Midnight Preprod 토큰을 포함해 `preview`나 `preprod` URL이 하나도 남아 있지 않고, `*.mainnet.midnight.network` indexer나 RPC URL도 남아 있지 않습니다. 그 endpoint들은 폐기되었습니다. [Environment reference](#environment-reference)를 참고하세요.
- [ ] **Blockfrost 토큰이 설정되었고 비공개로 유지된다.** 모든 indexer·RPC URL이 환경에서 읽어 온 Midnight Mainnet `project_id`를 담고 있으며, 토큰이 브라우저 코드에 실리지 않습니다. [Blockfrost: the mainnet indexer and RPC provider](#blockfrost-the-mainnet-indexer-and-rpc-provider)를 참고하세요.
- [ ] **배포 승인을 요청했다.** mainnet 컨트랙트 배포는 Midnight Foundation의 검토를 거칩니다. [contract deployment rubric](https://github.com/midnightntwrk/midnight-improvement-proposals/blob/main/deployments/contract-deployment-rubric.md)에 따라 DApp을 평가하고, MIP 저장소의 [`deployments/`](https://github.com/midnightntwrk/midnight-improvement-proposals/tree/main/deployments) 아래에 요청을 추가하는 pull request를 연 뒤, 배포 자격 증명을 기다리세요. 이 검토는 감사가 아닙니다. [How to work together to get your app deployed](/blog/how-to-apply-for-deployment-auth)를 참고하세요.
- [ ] **인프라 결정이 내려졌다.** Blockfrost 플랜이 예상 트래픽을 감당하거나, 자체 node와 indexer를 운영합니다.
- [ ] **키 관리가 정리되었다.** 컨트랙트와 자금을 통제하는 키에 소유자, 백업, 교체 경로가 있습니다. [Security and best practices](./security-best-practices)를 참고하세요.
- [ ] **프로덕션에서 DApp을 관찰할 수 있다.** 배포를 확인하고 활동을 지켜보는 데 어떤 [block explorer](#environment-reference)와 indexer 쿼리를 쓸지 알고 있습니다.
