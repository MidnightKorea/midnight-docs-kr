## Compact developer tools 0.5.3 release notes

Compact developer tools(devtools) 0.5.3은 툴체인 설치를 더 안정적으로 만드는 유지 보수 릴리스입니다. 이제 툴체인을 설치하는 데 `unzip`이 필요하지 않습니다. 설치가 도중에 실패하면 `compact update`를 다시 실행해 복구할 수 있습니다. 0.5.2에서는 재시도가 `compact compile`을 비롯한 다른 명령을 망가진 상태로 남길 수 있었습니다.

기존 devtools 설치가 있다면 `compact self update` 명령으로 업데이트할 수 있습니다. 이는 설치 스크립트로 설치한 경우에 동작합니다. `compact self update`가 `Unable to load receipt for app compact`로 실패하면, 대신 릴리스 페이지의 셸 명령으로 0.5.3을 설치하세요. 업그레이드를 확인하려면 `compact --version`을 실행하세요. `compact 0.5.3`을 출력합니다.

기존 devtools 설치가 없다면 [릴리스 페이지](https://github.com/midnightntwrk/compact/releases/tag/compact-v0.5.3)에 표시된 셸 명령으로 버전 0.5.3을 설치할 수 있습니다.

## Improvements

### Toolchain installs no longer need `unzip`

`compact update`가 이제 `unzip`을 실행하는 대신 툴체인 아카이브를 직접 풉니다. [devtools 0.5.2](/relnotes/compact-tools/compact-tools-0-5-2)에서는 `unzip`이 없는 시스템에서 툴체인 설치가 `Failed to spawn artifact extraction command`로 실패했습니다. WSL2에서의 기본 Ubuntu 24.04 이미지가 그런 시스템 중 하나입니다.

`compact update`는 아카이브를 풀 때 `../` 경로처럼 아카이브를 벗어나는 이름을 가진 항목도 거부합니다. 또한 풀어낸 파일에 `0755`보다 높은 권한을 절대 부여하지 않습니다.

### Help output wraps to your terminal

`compact --help`과 그 서브커맨드의 도움말이 이제 터미널 너비에 맞게 줄바꿈됩니다. 이전에는 긴 줄을 그대로 출력했습니다. `compact compile --help`은 컴파일러 자체의 도움말을 출력하므로 예외입니다.

## Bug fixes

### The next `compact update` repairs a failed install

이전 `compact update <version>`이 도중에 실패했다면, 다시 실행할 때 이제 `previous installation is incomplete, reinstalling`을 출력하고 해당 버전을 설치합니다. 이전에는 `already installed`를 보고한 뒤 `Expecting a file`로 실패했습니다([issue #739](https://github.com/LFDT-Minokawa/compact/issues/739)).

`compact update`는 이제 툴체인 파일을 스테이징 디렉터리에 푼 뒤 `compactc`를 마지막에 제자리로 옮깁니다. 중단된 설치가 완료된 것처럼 보이는 일이 결코 없습니다.

devtools를 업데이트해도 이전 실패로 망가진 버전은 복구되지 않습니다. 업데이트한 뒤 해당 버전에 대해 `compact update <version>`을 한 번 더 실행하세요. 그래도 `already installed`를 보고하지만 컴파일러가 실행되지 않으면 `~/.compact/versions/<version>`을 삭제한 뒤 `compact update <version>`을 다시 실행하세요.

### A failed install no longer breaks the default compiler

`compact`은 이제 바이너리가 없는 컴파일러를 기본값으로 설정하기를 거부합니다. 이전에는 재시도가 실패하면 기본값이 없는 바이너리를 가리킨 채 남을 수 있었습니다. 그러면 `compact check`, `compact list`, `compact compile`이 망가졌습니다. 기본 컴파일러가 이미 없는 바이너리를 가리키고 있다면, 이 명령들이 이제 그것을 재설치하는 `compact update <version>` 명령을 출력합니다.

### An unreadable archive no longer fails every retry

`compact update`가 툴체인 아카이브를 읽을 수 없으면 그 아카이브를 삭제하고 한 번 더 다운로드합니다. 이전에는 모든 재시도가 같은 읽을 수 없는 아카이브를 재사용해 실패했습니다. 디스크가 가득 찼거나 권한 문제가 있으면 새로 다운로드해도 도움이 되지 않으므로 설치를 즉시 중단합니다.

## Breaking changes

없음.

## Known issues

- devtools 0.5.3으로 툴체인 0.22.0 또는 0.23.0을 설치하면 `std.compact`이 툴체인의 플랫폼 디렉터리 안 `lib` 하위 디렉터리가 아니라 플랫폼 디렉터리 자체에 놓입니다. 예를 들어 `~/.compact/versions/0.23.0/aarch64-darwin/`에 놓입니다. 그러면 `include "std";`를 사용하는 스마트 컨트랙트가 `failed to locate file "std.compact"`로 컴파일에 실패합니다. 이를 우회하려면 `include "std";`를 `import CompactStandardLibrary;`로 바꾸거나, 해당 플랫폼 디렉터리에 `lib`을 만들고 `std.compact`을 그 안으로 옮기세요. 예를 들어 `~/.compact/versions/0.23.0/aarch64-darwin/lib/std.compact`입니다. 이 문제는 툴체인 0.24.0 이후, 또는 이전 버전의 devtools로 설치한 0.22.0 및 0.23.0에는 영향을 주지 않습니다.
