## 주요 변경 사항 요약

Midnight Indexer 4.3.2는 개발 라인의 patch 릴리스로, Midnight 1.1 번들에 포함되어 배포됩니다. indexer-api에 kubernetes probe 연동용 HTTP `/live` liveness 엔드포인트를 추가하고, 종료 신호가 처리 중인 wallet 항목을 놓칠 수 있던 `dustGenerations` subscription 버그를 수정합니다.

이 릴리스는 Node 1.0.0, Ledger 8.1.0과 페어링됩니다. Node 0.22.x를 운영 중이라면 이 릴리스가 아니라 4.0.x 유지보수 라인을 따라가세요.

:::caution
4.0.x 라인에서 4.3.2로 업그레이드하려면 indexer를 리셋하고 genesis부터 다시 인덱싱해야 합니다. mainnet/preprod 규모 기준 약 3~4일을 잡아 두세요. 4.3.x 라인 내부 업그레이드(4.3.0 → 4.3.1 → 4.3.2)는 리셋 없이 바로 적용됩니다.
:::

## 대상 독자

이 릴리스 노트는 다음과 같은 경우에 유용합니다:

- Node 1.0.0 이상을 대상으로 Midnight Indexer를 운영하는 operator
- `dustGenerations` subscription을 사용하는 wallet 연동 개발자
- indexer-api에 kubernetes liveness probe를 구성하는 SRE

Node 0.22.x를 운영 중인 operator는 이 릴리스가 아니라 4.0.x 유지보수 라인을 따라가야 합니다.

## 업데이트 요약

- indexer-api에 kubernetes liveness probe용 `/live` HTTP 엔드포인트 추가
- `dustGenerations` subscription 종료 판정을 wallet별 cursor 대신 체인 진행도 기준으로 수정
- storage drain과 체인 진행도 읽기 사이의 race window를 닫는 re-drain 단계 추가

## 신규 기능

이번 릴리스에 도입된 새로운 기능의 상세 내용입니다.

### kubernetes liveness probe용 `/live` HTTP 엔드포인트

indexer-api에 기존 `/ready` 엔드포인트와 나란히 HTTP `/live` 엔드포인트가 추가됩니다. SRE는 이를 kubernetes liveness probe로 구성할 수 있습니다. 기존의 파일 존재 검사(`cat /var/run/indexer-api/running`)는 HTTP 서버가 멈춘 상태를 감지하지 못했는데, 이를 대체합니다.

`/live`를 사용하면 indexer-api pod가 응답 불능 상태에 빠졌을 때 probe 실패 임계치를 넘는 시점에 kubelet이 재시작을 트리거해 자동 복구합니다.

이 기능은 opt-in입니다. 사용하려면 배포 manifest의 `livenessProbe`를 API 포트의 `/live`에 대한 `httpGet`으로 바꾸세요. 파일 존재 probe도 하위 호환을 위해 계속 동작합니다.

## 호환성 주의 사항 (Breaking changes)

v4.3.2에는 breaking change가 없습니다. indexer 4.x 개발 라인을 이미 사용 중인 operator는 바로 업그레이드할 수 있습니다.

---

## 버그 수정 및 품질 개선

이번 릴리스에 포함된 버그 수정 및 품질 개선 사항입니다.

### `dustGenerations` subscription 종료 판정 수정

사용자가 넘긴 `endIndex`가 wallet 소유 generation index와 일치하지 않으면 `dustGenerations` subscription이 live-tail 상태에서 멈출 수 있었습니다. 이제 종료 신호가 wallet별 cursor(`cursor > end_index` 엄격 비교) 대신 체인 진행도(`chain_first_free > end_index`)를 사용합니다. `dustNullifierTransactions`·`shieldedNullifierTransactions`와 같은 패턴입니다.

`Progress`를 내보내기 전의 re-drain 단계가 storage drain 종료와 체인 진행도 읽기 사이의 작은 race window를 닫습니다. 체인의 현재 `dustGenerationEndIndex`를 `endIndex`로 넘기는 wallet은 이제 깔끔하게 종료됩니다.

## 알려진 이슈

### 동시 merkle-tree-update 부하가 높을 때의 runtime-park 멈춤

동시 merkle-tree-update 부하가 높을 때, `Sp::force_as_arc`(collapsed-update 경로에서 `BackendLoader::get` 경유 호출)가 tokio runtime 전체를 무기한 멈출 수 있습니다. 이 상태의 pod는 kubelet의 `/live` probe가 실패해 컨테이너가 SIGTERM을 받을 때까지 로그를 전혀 내보내지 않습니다.

이 문제의 완화책 가운데 감지는 이번 릴리스의 `/live` HTTP 엔드포인트가, 복구는 kubernetes 재시작 경로가 담당합니다. 근본 원인 조사는 [midnight-ledger#521](https://github.com/midnightntwrk/midnight-ledger/issues/521)에서 진행 중입니다.
