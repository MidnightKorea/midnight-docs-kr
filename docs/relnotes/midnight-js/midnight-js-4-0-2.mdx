## 주요 변경 사항 요약

이번 릴리스는 shielded coin 흐름에서 실패를 유발하던 트랜잭션 구성 경로를 되돌려 v4.0.x 라인을 안정화합니다.

또한 proving provider 설정, contract 오류 타입, 보안 강화, 트랜잭션 처리 전반의 운영 안정성이 개선되었습니다.

## 대상 독자

이 릴리스 노트는 다음과 같은 개발자에게 유용합니다:

- v4.0.1로 업그레이드하고 `addCalls` 기반 call 트랜잭션 흐름을 적용한 경우
- shielded coin 작업을 사용하는 contract를 개발하는 경우
- 인증 헤더가 필요한 HTTP proof provider를 운영하는 경우
- Effect 기반 contract 오류에 대한 커스텀 오류 처리를 유지보수하는 경우

## 업데이트 요약

- `httpClientProvingProvider`에 커스텀 헤더 지원 추가
- 안전한 오류 타입 좁히기를 위한 `isEffectContractError` 타입 가드 추가
- shielded-call 안정성 복원을 위해 `createUnprovenLedgerCallTx` 내부 로직 되돌림
- contract 소유 spend 검증 전 Merkle-tree rehash 처리 수정
- deploy 흐름에서 compact 오류 전파 개선
- fallible 트랜잭션 오류 구성 및 리포팅 수정

## 신규 기능

이번 릴리스는 proving-provider 설정과 안전한 오류 처리를 위한 개발 편의성 기능을 추가합니다.

### `httpClientProvingProvider`의 헤더 지원

HTTP client proving provider가 proof server에 대한 모든 요청에 커스텀 헤더를 지원합니다. 인증 토큰, API 키 또는 기타 커스텀 헤더를 proof 생성 및 검증 요청에 함께 전송할 수 있습니다.

사용법:

```typescript
import { httpClientProvingProvider } from '@midnight-ntwrk/http-client-proof-provider';

const provider = httpClientProvingProvider(zkConfigProvider, proofServerUrl, {
  timeout: 60_000,
  headers: {
    'Authorization': 'Bearer <token>',
    'X-Custom-Header': 'value'
  }
});
```

API 인터페이스:

```typescript
export interface ProvingProviderConfig {
  readonly timeout?: number;
  readonly headers?: Record<string, string>;  // 신규
}
```

헤더는 `{ 'Content-Type': 'application/octet-stream' }`을 기본값으로 병합되므로, 커스텀 헤더가 기본값보다 우선합니다.

---

### `isEffectContractError` 타입 가드

`as any` 캐스팅 없이 Effect-ts contract 오류를 안전하게 좁힐 수 있는 새로운 타입 가드입니다. `unproven-call-tx.ts`와 `unproven-deploy-tx.ts`에서 내부적으로 사용되며, 커스텀 오류 처리를 위해 `@midnight-ntwrk/midnight-js-contracts`에서 export됩니다.

사용법:

```typescript
import { isEffectContractError } from '@midnight-ntwrk/midnight-js-contracts';

try {
  await executeCircuit();
} catch (error) {
  if (isEffectContractError(error) && error._tag === 'ContractRuntimeError') {
    // 캐스팅 없이 error.cause에 안전하게 접근
    console.error(error.cause.message);
  }
}
```

## 호환성 주의 사항 (Breaking changes)

이번 릴리스에는 새로운 breaking API가 없습니다. 다만, v4.0.1의 breaking change #4(`addCalls` 트랜잭션 구성 마이그레이션)가 되돌려졌으므로, 이미 v4.0.1에 맞춰 적응한 팀은 해당 변경 사항을 되돌려야 합니다.

### v4.0.1 `addCalls` 마이그레이션 되돌림

**변경 내용**: `createUnprovenLedgerCallTx` 동작이 v4.0.1의 `addCalls` 경로에서 v3.2.0 호환 `ContractCallPrototype`/`PartitionedTranscript` 방식으로 복원되었습니다.

**영향 범위**: v4.0.1의 `publicTranscript` + `ledgerParameters` call 시그니처로 마이그레이션한 구현체는 v4.0.2에서 실패하거나 호환되지 않을 수 있습니다.

**필요 조치**:
- `createUnprovenLedgerCallTx` 호출부에서 `publicTranscript`를 `partitionedTranscript: PartitionedTranscript`로 교체하세요.
- `createUnprovenLedgerCallTx` 호출 인수에서 `ledgerParameters`를 제거하세요(단, `CallOptionsProviderDataDependencies`의 `ledgerParameters`는 여전히 필수입니다).
- v4.0.1 호환 대응으로 제거했던 `extractUserAddressedOutputs` 사용을 복원하세요.

**복원된 API 형태**:

```typescript
// v4.0.2 복원된 형태
createUnprovenLedgerCallTx(
  circuitId: AnyProvableCircuitId,
  contractAddress: ContractAddress,
  initialContractState: ContractState,
  zswapChainState: ZswapChainState,
  partitionedTranscript: PartitionedTranscript,
  privateTranscriptOutputs: AlignedValue[],
  input: AlignedValue,
  output: AlignedValue,
  nextZswapLocalState: ZswapLocalState,
  encryptionPublicKey: EncPublicKey
): UnprovenTransaction
```

### 자주 발생하는 마이그레이션 문제

다음 런타임 오류는 v4.0.2로 업그레이드하고 v4.0.1의 `addCalls` 관련 적응 사항을 되돌리면 해결됩니다.

#### 오류: shielded 작업에서 "expected a cell, received null"

**원인**: v4.0.1 `addCalls` 스택 초기화가 `receiveShielded`, `sendShielded`, `writeCoin`을 사용하는 contract에서 불일치

**해결**: v4.0.2 트랜잭션 구성 경로(복원된 prototype 방식) 사용

#### 오류: "attempted to spend from a Merkle tree that was not rehashed"

**원인**: 포함 증명(inclusion proof) 구성 전에 chain state의 Merkle tree가 rehash되지 않음

**해결**: v4.0.2에서 `zswapStateToOffer`가 input 구성 전 `postBlockUpdate()`를 호출하도록 업데이트됨

## 버그 수정

트랜잭션 구성, fallible 트랜잭션 리포팅, deploy 시 오류 전파의 정확성과 안정성 문제가 해결되었습니다.

### `createUnprovenLedgerCallTx`를 `ContractCallPrototype` 방식으로 복원

v4.0.1에서 도입된 `PreTranscript + Transaction.addCalls()` 방식은 shielded coin 작업(`receiveShielded`, `sendShielded`, `writeCoin`)을 사용하는 contract에서 실패합니다. `addCalls()` 스택 머신이 circuit 실행 시 compact-runtime의 `queryLedgerState`와 동일하게 스택을 초기화하지 않아, shielded 작업이 초기 스택의 항목을 기대하는 `dup` 연산을 생성할 때 `"expected a cell, received null"` 오류가 발생합니다.

`createUnprovenLedgerCallTx`를 `ContractCallPrototype + Intent.addCall()`과 `PartitionedTranscript`를 사용하는 방식으로 복원하여 shielded coin 작업을 올바르게 처리합니다.

**영향받는 contract**: `receiveShielded`, `sendShielded`, `writeCoin`을 사용하는 모든 contract(예: Seabattle `join_p1`/`join_p2`, Lunarswap `addLiquidity`)

### contract 소유 spend 전 `ZswapChainState` rehash

ledger-v8의 `ZswapInput.newContractOwned`는 coin 포함 증명 검증 전에 chain state의 Merkle tree가 rehash되어 있어야 합니다. `zswapStateToOffer` 함수가 input 구성 전에 chain state에서 `postBlockUpdate()`를 호출하도록 변경되었습니다. 이 처리가 없으면, 이전 트랜잭션에서 예치된 coin을 사용하는 contract(예: Seabattle `join_p2`에서 `join_p1`의 coin에 `mergeCoinImmediate` 호출)가 `"attempted to spend from a Merkle tree that was not rehashed"` 오류와 함께 실패합니다.

### `createUnprovenDeployTxFromVerifierKeys`에서 `CompactError` 전파 수정

`createUnprovenDeployTxFromVerifierKeys`의 오류 핸들러가 contract 런타임 오류 해제 시 `ContractRuntimeError`만 확인했습니다. `compact-js` 의존성이 `initialState` 오류를 `ContractConfigurationError`로 래핑하도록 변경되어, 핸들러가 `ContractRuntimeError`와 `ContractConfigurationError`를 모두 인식하도록 업데이트되었습니다. 이로써 `CompactError` 메시지가 호출자에게 올바르게 전파됩니다.

### Fallible offer 오류 리포팅 수정

fallible 트랜잭션 오류 리포팅의 두 가지 버그가 수정되었습니다:

- **`TxFailedError`의 Map 직렬화**: `JSON.stringify`에서 `Map`이 네이티브로 직렬화되지 않아 `segmentStatusMap`이 무시되던 문제. replacer가 `Object.fromEntries`로 `Map` 인스턴스를 일반 객체로 변환하도록 수정되었습니다.
- **scoped 트랜잭션 오류의 잘못된 `scopeName`**: 오류 메시지가 resolved된 `txOptions` 대신 `options` 파라미터(중첩 트랜잭션에서만 설정됨)를 참조하여, root 트랜잭션이 `scopeName`을 지정했어도 항상 `<unnamed>`으로 표시되던 문제.

### Fallible 오류 처리 수정

fallible 트랜잭션 처리에서 오류 객체가 잘못 구성되던 문제가 수정되었습니다.

### 오류의 `as any` 캐스트를 타입 가드로 교체

`errors.ts`에 `isEffectContractError` 타입 가드를 도입하여, 취약한 `(error as any)` 인트로스펙션 대신 Effect-ts 오류를 안전하게 좁힐 수 있게 되었습니다. `unproven-call-tx.ts`와 `unproven-deploy-tx.ts`의 catch 블록에서 모든 `as-any` 캐스트와 `eslint-disable` 주석이 제거되었습니다.
