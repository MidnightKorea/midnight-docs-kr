* **Version**: v4.1.0
* **Date**: May 20, 2026
* **Node.js requirement**: >=22

---

## High-level summary

이번 릴리스는 스토리지 암호화를 플러그인형 백엔드를 갖춘 Web Crypto API로 옮겨, `level-private-state-provider`를 브라우저와 React Native에서 사용할 수 있게 합니다. 또한 `@midnight-ntwrk/midnight-js-protocol`을 도입합니다. 이 패키지는 ledger, Compact runtime, Compact.js, on-chain runtime, Platform JS 패키지를 버전 비종속 서브패스 뒤로 다시 export합니다. 두 변경 모두 `StorageEncryption`을 직접 생성하거나 protocol 패키지를 직접 import하는 코드에는 호환성을 깨는 변경입니다. 이 밖에도 여러 보안 수정과, fallible 세그먼트 circuit 연산의 shielded 코인 라우팅 수정이 포함됩니다.

## Audience

다음에 해당하는 개발자에게 특히 중요합니다:

- `StorageEncryption`을 직접 생성하거나 그 `encrypt`, `decrypt`, `verifyPassword` 메서드를 호출하는 경우
- Midnight.js 애플리케이션에서 `@midnight-ntwrk/ledger-v8`, `@midnight-ntwrk/compact-runtime`, `@midnight-ntwrk/compact-js`, `@midnight-ntwrk/onchain-runtime-v3`, `@midnight-ntwrk/platform-js`에서 타입이나 함수를 import하는 경우
- 브라우저나 React Native용 DApp을 개발하는 경우
- fallible 세그먼트에서 실행되는 circuit에서 shielded 토큰을 발행하거나 이동하는 경우

## Summary of updates

- `StorageEncryption`을 `StorageEncryption.create()` 팩토리를 갖춘 비동기 Web Crypto API로 이전했습니다(호환성 깨짐).
- protocol 패키지용 버전 비종속 서브패스를 제공하는 `@midnight-ntwrk/midnight-js-protocol`을 추가했습니다. ESLint 규칙이 직접 import를 차단합니다(호환성 깨짐).
- Noble 순수 JS 폴백을 갖춘 `CryptoBackend` 추상화와 React Native용 주입 가능한 `levelFactory`를 추가했습니다.
- 엔드투엔드 테스트에서 지갑에 위임하는 증명을 위해 `DAppConnectorWalletAdapter`와 `DAppConnectorInitialAPI`를 `testkit-js`에 추가했습니다.
- 인메모리 SHA-256 비밀번호 검증기를 PBKDF2로 교체하고, ZK config provider와 `VersionManager`에서 경로 순회를 차단했으며, `decryptValue`가 실패 시 안전하게 닫히도록 했습니다.
- fallible 세그먼트 circuit 연산이 만든 shielded 코인을 올바른 Zswap offer로 라우팅합니다.
- `midnight-js-contracts`에서 Node 전용 `fs`·`path` import를 제거해 브라우저용으로 번들링되도록 했습니다.

## New features

### Web Crypto storage encryption with a pluggable backend

`level-private-state-provider`의 `StorageEncryption`이 Node.js `crypto` 모듈 대신 `globalThis.crypto.subtle`을 사용합니다. `levelPrivateStateProvider`의 `cryptoBackend` 옵션으로 `'webcrypto'`(사용 가능할 때 기본값)와 `'noble'` 중 하나를 선택합니다. `'noble'`은 보안 컨텍스트가 없는 환경을 위해 `@noble/ciphers`와 `@noble/hashes` 기반으로 만든 순수 JS 폴백입니다. 새 타입 export: `CryptoBackend`, `CryptoBackendType`, `StorageEncryptionOptions`. ([#798](https://github.com/midnightntwrk/midnight-js/pull/798), [#827](https://github.com/midnightntwrk/midnight-js/pull/827))

### Injectable `levelFactory` for React Native

`LevelPrivateStateProviderConfig`가 선택적 `levelFactory`를 받으므로, `AbstractLevel` 호환 저장소라면 무엇이든 기본 Node.js `Level`을 대체할 수 있습니다. 덕분에 React Native 사용자의 제약이 풀립니다. 새 export: `LevelFactory`, `DatabaseLevel`. ([#827](https://github.com/midnightntwrk/midnight-js/pull/827))

### Protocol package

`@midnight-ntwrk/midnight-js-protocol`은 외부 protocol 패키지 다섯 개를 `@midnight-ntwrk/midnight-js-protocol/ledger`, `@midnight-ntwrk/midnight-js-protocol/compact-runtime` 같은 서브패스 뒤로 감쌉니다. 그래서 향후 ledger나 runtime 업그레이드가 이 패키지만 바꾸면 됩니다. ([#832](https://github.com/midnightntwrk/midnight-js/pull/832))

### `DAppConnectorWalletAdapter` in testkit-js

`DAppConnectorWalletAdapter`는 로컬 WASM 증명을 사용해 `MidnightWalletProvider`를 `ConnectedAPI` 인터페이스 뒤로 감싸고, `DAppConnectorInitialAPI`는 network ID 검증을 포함한 `InitialAPI`를 제공합니다. 덕분에 DApp Connector 증명 흐름을 독립 proof server 없이 엔드투엔드로 테스트할 수 있습니다. ([#855](https://github.com/midnightntwrk/midnight-js/pull/855))

### Input validation helpers

`@midnight-ntwrk/midnight-js-utils`의 `assertSafeName`과 `assertSemVer`는 비어 있거나, 지나치게 길거나, 경로 순회를 포함하거나, semver가 아닌 입력을 거부합니다. ([#875](https://github.com/midnightntwrk/midnight-js/pull/875))

## Breaking changes

### `StorageEncryption` is async

생성자가 비동기 팩토리 `StorageEncryption.create(password)`로 대체되고, `encrypt`, `decrypt`, `verifyPassword`, `decryptWithPassword`, `invalidateEncryptionCache`가 promise를 반환합니다. `isDecryptionError`는 Web Crypto `DOMException` 메시지를 인식합니다.

```typescript
// Before (v4.0.4)
const encryption = new StorageEncryption(password);
const encrypted = encryption.encrypt(data);

// After (v4.1.0)
const encryption = await StorageEncryption.create(password);
const encrypted = await encryption.encrypt(data);
```

### Protocol imports go through `midnight-js-protocol`

protocol 패키지에서의 직접 import는 아래 서브패스로 대체됩니다. ESLint `no-restricted-imports` 규칙이 옛 형태를 보고합니다.

| Before (v4.0.4) | After (v4.1.0) |
|---|---|
| `@midnight-ntwrk/ledger-v8` | `@midnight-ntwrk/midnight-js-protocol/ledger` |
| `@midnight-ntwrk/compact-runtime` | `@midnight-ntwrk/midnight-js-protocol/compact-runtime` |
| `@midnight-ntwrk/compact-js` | `@midnight-ntwrk/midnight-js-protocol/compact-js` |
| `@midnight-ntwrk/onchain-runtime-v3` | `@midnight-ntwrk/midnight-js-protocol/onchain-runtime` |
| `@midnight-ntwrk/platform-js` | `@midnight-ntwrk/midnight-js-protocol/platform-js` |

### Behaviour changes to be aware of

- `verifyPassword`가 단일 SHA-256 라운드 대신 PBKDF2(60만 회 반복)를 실행하므로, 캐시 미스 이후의 콜드 리드는 수백 밀리초가 걸립니다. 이후 읽기는 캐시된 키를 사용합니다. 디스크 상의 형식은 그대로입니다. ([#883](https://github.com/midnightntwrk/midnight-js/pull/883))
- `assertDefined`와 `assertUndefined`가 falsy 값(`0`, `''`, `false`, `0n`)을 허용합니다. 기존의 truthiness 검사에 의존하던 코드에는 명시적 조건식이 필요합니다. ([#900](https://github.com/midnightntwrk/midnight-js/pull/900))
- `decryptValue`가 비밀번호 교체 중 인식할 수 없는 데이터를 만나면 원시 바이트를 반환하는 대신 예외를 던집니다. ([#885](https://github.com/midnightntwrk/midnight-js/pull/885))

## Bug fixes and quality improvements

### Shielded coins routed to the correct segment

`createUnprovenLedgerCallTx`가 shielded 입력과 출력을, 그것을 만들어 낸 circuit 세그먼트와 상관없이 모두 guaranteed Zswap offer에 넣었습니다. 그래서 fallible 세그먼트 연산이 발행한 코인이 `InsufficientFunds`로 밸런싱에 실패했습니다. 이제 `zswapStateToSegmentedOffer`가 각 코인을 분할된 transcript에 대조해 guaranteed offer와 fallible offer를 따로 만듭니다. 세그먼트가 모호한 경우에는 조용히 폴백하지 않고 예외를 던집니다. ([#876](https://github.com/midnightntwrk/midnight-js/pull/876), [#877](https://github.com/midnightntwrk/midnight-js/pull/877))

### Browser-bundleable `midnight-js-contracts`

`logTransaction()`이 디버그 트레이스를 쓰기 위해 `node:fs`와 `node:path`를 더 이상 import하지 않으므로, `@midnight-ntwrk/midnight-js-contracts`가 브라우저용으로 번들링됩니다. ([#869](https://github.com/midnightntwrk/midnight-js/pull/869))

### Path traversal blocked in ZK providers and `VersionManager`

`node-zk-config-provider`와 `fetch-zk-config-provider`에서 경로나 URL을 만들기 전에 `circuitId`를 검증하고, `compact/version-manager`에서는 `getVersionDir`가 유일한 검증 지점으로서 삭제 전에 포함 관계를 확인합니다. ([#875](https://github.com/midnightntwrk/midnight-js/pull/875))

### HTML responses rejected by `FetchZkConfigProvider`

싱글 페이지 앱 서버는 존재하지 않는 아티팩트 경로에 대해 HTTP 200과 함께 `index.html`을 반환합니다. 이제 provider가 콘텐츠 타입을 확인해, URL과 상태 코드를 담은 오류와 함께 `text/html`을 거부합니다. ([#785](https://github.com/midnightntwrk/midnight-js/pull/785))

### Dependencies

`@apollo/client`이 3.14.0에서 4.1.6으로, `compactc`가 0.31.0으로 올라가고 테스트 픽스처를 다시 컴파일했으며, testkit-js가 개별 `wallet-sdk-*` 패키지 대신 `@midnight-ntwrk/wallet-sdk` barrel 패키지 1.0.0을 사용합니다. ([#666](https://github.com/midnightntwrk/midnight-js/pull/666), [#902](https://github.com/midnightntwrk/midnight-js/pull/902), [#862](https://github.com/midnightntwrk/midnight-js/pull/862))
