## High-level summary

Node v0.22.0은 Ledger 8.0.2로 업그레이드되며 거버넌스, 안정성, 운영 측면의 중요한 개선을 도입한 메이저 릴리스입니다. 계정별 거버넌스 트랜잭션 스로틀링을 추가하고, 런타임 안전성 검사를 강화하며, 운영 네트워크 환경을 위한 제네시스 생성과 검증 도구를 확장합니다.

또한 이번 릴리스는 ledger 저장 레이아웃을 v2로 변경하므로, 제네시스에서 새로 동기화하거나 호환되는 스냅샷을 사용해야 합니다.

---

## Audience

이 릴리스 노트는 다음에 해당하는 사용자를 대상으로 합니다.

- Midnight 노드 인프라 또는 검증자 운영을 담당하는 사용자
- 거버넌스 및 시스템 매개변수 워크플로를 관리하는 사용자
- Node RPC API 및 체인 운영과 통합하는 사용자
- 트랜잭션 및 인텐트 워크플로에 Midnight toolkit을 사용하는 사용자

---

## What changed (Summary of updates)

이번 릴리스의 주요 변경 사항은 다음과 같습니다.

- 런타임 ledger 통합을 v7에서 v8.0.2로 업그레이드
- 거버넌스 멤버 계정별 서명 트랜잭션 스로틀링 추가
- 권한 작업의 안전성을 높이기 위한 거버넌스 시스템 트랜잭션 게이팅 추가
- `Op::Deploy`와 `Op::Maintain` 트랜잭션을 필터링하는 `--filter-deploy-txs` 추가
- 네트워크 출범 및 마이그레이션 워크플로를 위한 제네시스 생성/검증 도구 추가
- 메모리 헤드룸 모니터링과 피어 평판/언밴 RPC 엔드포인트 추가
- 쓰기 비용 동작 개선을 위한 ledger 저장 레이아웃 v2 적용
- 노드 운영 전반의 결정론, 관찰 가능성, 툴킷 회복력 개선

## New features

이번 릴리스에서 새롭게 도입된 기능은 다음과 같습니다.

### Ledger 8.0.2 integration

Node v0.22.0은 런타임 업그레이드를 통해 Ledger 8.0.2로 업그레이드됩니다. 이를 통해 새로운 ledger 동작과 수정 사항이 도입되며, 노드와 툴킷의 흐름이 최신 ledger API에 맞춰 정렬됩니다.

### Per-account transaction throttling

새로 도입된 스로틀 메커니즘은 거버넌스 멤버 계정별로 일정한 시간 윈도 동안 서명된 트랜잭션 처리량을 제한합니다. 이를 통해 거버넌스 경로 악용 위험을 줄이면서, 일반 inherent 및 unsigned 트랜잭션 흐름은 그대로 처리합니다.

### Governance and genesis tooling updates

이번 릴리스는 시스템 트랜잭션 디스패치에 대한 거버넌스 통제를 강화하고, 네트워크 출범 및 환경 구축에 사용되는 스크립트와 검증 명령을 포함해 제네시스 생성/검증 도구를 확장합니다.

### Operational features for node operators

노드 운영자가 사용할 수 있는 새 제어 기능과 진단 도구가 추가되었습니다.

- 권한 기반 배포 단계에서 사용하는 `--filter-deploy-txs`
- 정상 종료(graceful shutdown) 동작이 적용된 메모리 헤드룸 모니터링
- 네트워크 문제 해결을 위한 피어 평판 및 언밴 RPC 엔드포인트

---

## New features requiring configuration updates

- **ledger 저장 레이아웃 v2**: 이전 버전의 디스크상 체인 데이터는 호환되지 않습니다.
- **배포 트랜잭션 필터링**: 권한 기반 컨트랙트 배포 정책이 필요한 경우 `--filter-deploy-txs`를 사용하세요.
- **메모리 헤드룸 모니터링**: 필요할 때 `--memory-threshold <MiB>`로 활성화하세요.

## Improvements

이번 릴리스는 런타임 동작, 쿼리 경로, 툴킷 워크플로, 릴리스 엔지니어링 전반에 걸쳐 안정성과 성능을 개선합니다.

- 검증 캐시는 이제 TTL(60초)과 TimeToIdle(TTI)을 함께 사용하여 릴레이 노드에서 오래된 항목을 제거합니다
- 블록 생산은 결정론적이며, 과거 블록의 동기화는 비결정론적인 상태로 유지됩니다
- QANet, Preview, Preprod에서 과거 블록에 대한 UTXO 정렬 오버라이드를 사용할 수 있습니다
- 트랜잭션 처리는 이제 `HashMap` 대신 결정론적 순회가 가능한 컬렉션을 사용합니다
- ledger 작업 시 단계별 시간 측정 로그를 추가로 기록합니다
- mainchain follower 작업은 이제 `observed_async_trait` 매크로를 통해 메트릭을 노출합니다
- `ma_tx_out`(`tx_out_id`, `ident`)에 복합 인덱스를 추가하여 제네시스 쿼리 속도를 높였습니다
- 오프라인 서브커맨드는 이제 하드코딩된 기본값 대신 체인 스펙에서 제네시스 상태를 도출합니다

## Breaking changes

운영자와 통합 담당자가 알아야 할 호환성을 깨는 변경과 필요한 조치는 다음과 같습니다.

### Ledger upgrade from 7 to 8.0.2

**변경 사항**: 런타임 ledger 통합이 v7에서 v8.0.2로 변경되었습니다.

**영향**: 런타임 활성화 전에 업그레이드되지 않은 노드는 블록 가져오기 또는 생산을 중단할 수 있습니다.

**필요한 조치**:

- 런타임 활성화 전에 노드 바이너리를 v0.22.0으로 업그레이드하세요.
- 런타임 업그레이드 적용 상태를 검증하고 업그레이드 진행 상황을 면밀히 모니터링하세요.

### Ledger storage layout v2

**변경 사항**: ledger 저장 레이아웃이 v2로 전환되었습니다.

**영향**: 이전 릴리스의 체인 데이터 디렉터리는 호환되지 않습니다.

**필요한 조치**:

1. 노드를 중지합니다.
2. 기존 체인 데이터를 제거합니다.
3. 제네시스에서 다시 동기화하거나 v2 호환 스냅샷을 사용합니다.

### Toolkit API behavior adjustments

**변경 사항**: `WalletSeed`의 `Default` 구현이 제거되었습니다. `contract-address`와 `coin-public` 입력에 untagged 디코딩이 사용됩니다.

**영향**: 묵시적인 wallet seed 기본값이나 tagged 전용 디코딩 가정에 의존하던 도구나 스크립트가 영향을 받습니다.

**필요한 조치**:

- 필요한 곳에 명시적인 wallet seed 값을 지정하세요.
- 영향을 받는 CLI 및 자동화 입력값을 그에 맞게 갱신하세요.
