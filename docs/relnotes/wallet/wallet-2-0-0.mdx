## High-level summary

이번 릴리스는 Wallet SDK의 아키텍처 분리에 초점을 맞추었습니다. proving, submission, 대기 트랜잭션 추적은 이제 `WalletFacade`가 소유하는 독립 서비스로 분리되었습니다.
shielded, unshielded, DUST 지갑 전반에 걸쳐 Wallet API가 표준화되었고, `WalletFacade`는 이제 proving이나 submission 실패 시 트랜잭션을 자동으로 되돌립니다.
HTTP prover server 모드의 대안으로 WASM 기반 proving도 새로 도입되었습니다.

---

## Audience

이번 릴리스는 다음 개발자에게 해당됩니다.

- Midnight 네트워크용 지갑을 구축하는 개발자
- DApp에 Midnight 토큰 전송을 통합하는 개발자
- 차폐(프라이빗) 및 비차폐 토큰 잔액을 관리해야 하는 개발자
- 당사자 간 원자적 스왑을 구현하는 개발자

## What changed (Summary of updates)

아래 요약은 구조적 변경과 개발자 대상 변경의 핵심을 정리합니다.

- proving을 독립 `ProvingService`로 분리하여 server(HTTP), WASM, simulator 모드를 지원
- 트랜잭션 submission을 독립 `SubmissionService`로 분리
- TTL/상태를 모니터링하고 실패한 트랜잭션을 자동으로 되돌리는 신규 `PendingTransactionsService`
- `WalletFacade` 초기화가 정적 async `WalletFacade.init()`으로 변경
- `WalletFacade`가 proving 또는 submission 실패 시 자동으로 트랜잭션 revert
- shielded, unshielded, DUST 지갑 전반에 걸쳐 Wallet API 표준화 (이름 변경 및 신규 메서드)
- 지갑 유형 간 공유 사용을 위해 `SyncProgress`를 `wallet-sdk-abstractions`로 이동
- 비차폐 트랜잭션 이력에 각 항목마다 생성/지출된 UTXO 포함
- `IndexerClientConnection`에 선택적 `keepAlive` 설정 추가
- Web Worker 기반 WASM proving provider 제공
- Node 클라이언트가 WebSocket을 on-demand로 연결하여 service worker 타이머 누수 방지

## New features

이번 릴리스에 도입된 새로운 기능의 상세 내역입니다.

### Standalone proving service

proving이 개별 지갑 빌더에서 분리되어 `@midnight-ntwrk/wallet-sdk-capabilities`의 독립 `ProvingService`가 되었습니다.
통합 설정을 통해 server(HTTP prover), WASM, simulator 모드를 지원합니다.
이제 `WalletFacade`가 proving을 소유하고, 실패 시 세 가지 지갑 유형 모두에서 트랜잭션을 revert 합니다.

**예시**: [wasm-prover.ts](https://github.com/midnightntwrk/midnight-wallet/blob/main/packages/docs-snippets/src/snippets/wasm-prover.ts)

### Standalone submission service

트랜잭션 submission이 `@midnight-ntwrk/wallet-sdk-capabilities`의 독립 `SubmissionService`로 분리되어 `WalletFacade`에 통합되었습니다. submission 실패 시 facade가 트랜잭션을 revert 합니다.

### Pending transactions service

`@midnight-ntwrk/wallet-sdk-capabilities`의 이 신규 서비스는 제출된 트랜잭션의 TTL과 인덱서 상태를 모니터링합니다. 대기 중인 트랜잭션이 실패로 보고되면 지갑 상태를 자동으로 되돌립니다. 서비스 상태는 직렬화 가능하므로, 지갑을 재시작해도 대기 트랜잭션 정보가 유지됩니다.

### WASM proving provider

원격 prover server의 대안으로 Web Worker 기반 proof 생성이 추가되었습니다. `ProverClient.WasmConfig`로 설정합니다. Filecoin 키 대신 Midnight 전용 키 자료를 사용합니다.

**예시**: [wasm-prover.ts](https://github.com/midnightntwrk/midnight-wallet/blob/main/packages/docs-snippets/src/snippets/wasm-prover.ts)

### 커스텀 prover 통합

`HttpProverClient`와 `WasmProver`에 기저 proving provider를 노출하는 `asProvingProvider()`가 추가되었습니다. `create()` 팩토리 함수는 Effect 레이어 없이 직접 인스턴스화할 수 있게 합니다. `Proving` 모듈의 `fromProvingProvider()`와 `fromProvingProviderEffect()` 헬퍼는 커스텀 prover 워크플로를 가능하게 합니다.

### DUST 등록 수수료 결제와 등록 해제

DUST 등록 트랜잭션에서 수수료 결제가 이제 선택 파라미터입니다. 등록 해제와 재지정 플로우가 지원됩니다. `UtxoWithMeta`에 `registeredForDustGeneration` 플래그가 추가되었습니다.

**예시**: [deregistration.ts](https://github.com/midnightntwrk/midnight-wallet/blob/main/packages/docs-snippets/src/snippets/deregistration.ts)

### UTXO가 포함된 비차폐 트랜잭션 이력

비차폐 지갑의 각 `TransactionHistoryEntry`에 이제 `createdUtxos`와 `spentUtxos` 배열이 포함됩니다. 각 UTXO는 `value`, `owner`, `tokenType`, `intentHash`, `outputIndex`를 노출합니다.

### 공유 sync progress

`SyncProgress`가 `wallet-sdk-shielded/v1`에서 `wallet-sdk-abstractions`로 이동하여, 차폐 패키지를 import하지 않고도 지갑 구현 전반에 걸쳐 사용할 수 있습니다.

### Promise 기반 쿼리 러너

이번 릴리스는 `@midnight-ntwrk/wallet-sdk-indexer-client`에 Effect 보일러플레이트 없이 GraphQL 쿼리를 실행하는 유틸리티를 추가합니다.

## New features requiring configuration updates

지갑이 새로운 아키텍처를 사용하도록 설정하려면 다음 업데이트가 필요합니다.

### Wallet facade에서 proving service 필수

이제 `WalletFacade.init()`은 `ProvingService`를 명시적으로 또는 `DefaultConfiguration`을 통해 받아야 합니다.

**필요한 업데이트**: `WalletFacade.init()` 호출 시 `ProvingService`를 전달하거나, `DefaultProvingConfiguration`(설정에 `provingServerUrl` 필요)을 포함하는 `DefaultConfiguration`을 사용하세요.

**영향**: `WalletFacade`는 더 이상 자체 proving service를 수반하는 지갑 빌더를 받지 않습니다. proving은 이제 facade 레벨의 관심사입니다. `DefaultConfiguration`의 `provingServerUrl` 필드는 기본 HTTP proving 모드에서 계속 동작합니다.

## Improvements

이번 릴리스에는 SDK 컴포넌트 전반에 걸친 편의성과 안정성 개선도 포함되어 있습니다.

- `WalletFacade.init()`이 이제 설정 객체를 받습니다. 이를 통해 향후 초기화 변경이 기존 통합을 깨지 않도록 할 수 있습니다.
- `IndexerClientConnection`과 `SubscriptionClient.ServerConfig`에 선택적 `keepAlive` 파라미터(기본 15,000 ms)가 추가되었고, 이는 기저 `graphql-ws` 클라이언트로 전달됩니다.
- Node 클라이언트(`@midnight-ntwrk/wallet-sdk-node-client`)가 이제 WebSocket을 on-demand로 연결하고 각 작업 후 끊어, `@polkadot/api` 헬스체크 타이머가 service worker를 살려두지 못하게 합니다.
- DUST 지갑의 `CoreWallet`이 class에서 plain object 타입과 namespace 조합으로 리팩터링되어 조합성이 향상되었습니다.
- DUST 지갑에 구조적 오류 처리용 `WalletError` 타입이 추가되었습니다.

## Breaking changes

이번 릴리스에는 마이그레이션이 필요한 API와 타입 수준의 변경이 다수 포함됩니다.

### `SerializedUnprovenTransaction`이 `SerializedTransaction`으로 대체

`SerializedUnprovenTransaction`이 `@midnight-ntwrk/wallet-sdk-abstractions`에서 제거되었습니다. 대신 직렬화된 트랜잭션 바이트를 담는 단순화된 타입인 `SerializedTransaction`을 사용하세요.

### 차폐 지갑 (`@midnight-ntwrk/wallet-sdk-shielded`)

- `ShieldedWalletAPI`에서 `finalizeTransaction` 제거 (`WalletFacade`가 처리)
- `@midnight-ntwrk/wallet-sdk-shielded/v1`에서 `Proving` export 제거
- V1 빌더와 `RunningV1Variant.Context`에서 `provingService` 제거
- `V1Builder`에서 `withProving` / `withProvingDefaults` 제거
- `DefaultV1Configuration`에 더 이상 `DefaultProvingConfiguration` 미포함
- `startWithShieldedSeed()`가 `startWithSeed()`로 이름 변경
- 전송 메서드의 `receiverAddress` 파라미터 타입이 `string`에서 `ShieldedAddress`로 변경
- `ShieldedWalletAPI`에 `getAddress(): Promise<ShieldedAddress>` 추가

### DUST 지갑 (`@midnight-ntwrk/wallet-sdk-dust-wallet`)

- `DustCoreWallet`이 `CoreWallet`으로 이름 변경
- `DustWalletState`에서 `walletBalance()`가 `balance()`로 이름 변경
- 상태 객체에서 `dustPublicKey`→`publicKey`, `dustAddress`→`address`로 변경
- `KeysCapability`에서 `getDustPublicKey()`→`getPublicKey()`, `getDustAddress()`→`getAddress()`로 변경
- `DustWalletAPI`에 `getAddress(): Promise<DustAddress>` 추가
- 트랜잭션 메서드의 `dustReceiverAddress` 파라미터 타입이 `string`에서 `DustAddress`로 변경
- `DustWalletAPI`에서 `proveTransaction` 제거
- V1 빌더와 `RunningV1Variant.Context`에서 `provingService` 제거
- `V1Builder`에서 `withProving` / `withProvingDefaults` 제거

### Facade (`@midnight-ntwrk/wallet-sdk-facade`)

- `UnboundTransaction`은 더 이상 facade 패키지에서 export되지 않습니다. `@midnight-ntwrk/wallet-sdk-capabilities/proving`에서 import하세요.
- `CombinedTokenTransfer`가 `ShieldedTokenTransfer`와 `UnshieldedTokenTransfer`로 분리되었으며, union 타입 `CombinedTokenTransfer`는 그대로 남습니다.
- `TokenTransfer`는 이제 `string` 대신 타입이 지정된 주소(`ShieldedAddress` 또는 `UnshieldedAddress`)를 요구합니다. 주소 인코딩은 내부에서 처리됩니다.
- `WalletFacade` 생성자가 정적 async 메서드 `WalletFacade.init()`으로 대체
- `WalletFacade`가 이제 `ProvingService`를 필수로 요구하며, `DefaultConfiguration`에는 `DefaultProvingConfiguration`이 포함됩니다.

마이그레이션 예시:

```ts
// Before
const address = MidnightBech32m.encode('undeployed', state.shielded.address).toString();
wallet.transferTransaction([{ type: 'shielded', outputs: [{ receiverAddress: address, ... }] }]);

// After
const address = await wallet.shielded.getAddress();
wallet.transferTransaction([{ type: 'shielded', outputs: [{ receiverAddress: address, ... }] }]);
```

## Known issues

이 섹션은 이번 Wallet SDK 릴리스의 알려진 이슈를 나열합니다.

### 차폐와 DUST 지갑에 대한 트랜잭션 이력 미구현

차폐 지갑과 DUST 지갑은 트랜잭션 이력을 추적하지 않습니다. 차폐 지갑의 트랜잭션 이력 getter는 "not yet implemented"를 던집니다. 비차폐 지갑만 트랜잭션 기록을 유지합니다.

### 차폐 트랜잭션 제출 실패 후 대기 코인이 해제되지 않음

차폐 트랜잭션 제출이 실패할 때, 차폐 지갑에서 대기 중으로 표시된 코인이 자동으로 해제되지 않을 수 있습니다.

**해결 방법**: 지갑을 재시작하거나 재동기화하여 남아있는 대기 상태를 해제하세요.

## Fixed defect list

이번 릴리스에 포함된 결함 수정은 다음과 같습니다.

- `rollbackSpendByUtxo`가 UTXO가 없을 때 더 이상 throw하지 않아 sync와 revert 작업 간 경쟁 조건을 해소 — UTXO를 찾지 못한 경우 상태를 변경하지 않고 그대로 반환합니다.
- `addSignature`가 generic 파라미터를 통해 입력 트랜잭션 타입을 보존합니다(이전에는 항상 `UnprovenTransaction`을 반환).
- `addSignature`에서 직렬화/역직렬화를 통한 Intent 복제를 제거했습니다.
- 여러 코인 지출에 걸친 대기 DUST 누적 문제를 수정했습니다.
- DUST 지갑 revert 시 TTL 처리에 대기 지출 ctime이 아닌 intent 지출 시각을 사용합니다.
- `fromStream`이 조기 unsubscribe 시 hub subscriber를 남기지 않도록 수정했습니다.
